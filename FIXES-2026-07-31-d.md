# mood8 — round 4 (2026-07-31): web tutorial + challenge join-request approval

1) WEB TUTORIAL DOESN'T FIT / ALIGN
   On the WEB version, the onboarding tutorial (coach-marks / highlight overlay / tooltips) does
   not fit or line up with the actual UI elements — highlighted boxes and tooltips are misaligned
   / off-position on web. Fix so the tutorial correctly measures and points to the real target
   elements on web (correct target rects, responsive positioning across window sizes). Verify on
   the live web build at https://mood8.app/app.

2) JOIN-REQUEST -> OUT-OF-APP NOTIFICATION
   When a user sends a request to JOIN a challenge, send an out-of-app (push) notification to the
   challenge owner/creator: e.g. "<name> requested to join your challenge <title>." Use the
   existing push system (real OS delivery still depends on FCM being configured; in-app + logged
   push should work now). If challenges are currently open-join, introduce a request model so
   joining a challenge can require owner approval.

3) TAP REQUEST -> APPROVE / DENY PAGE
   Tapping the join-request notification (and the request shown in-app) opens an Approve / Deny
   screen where the owner can approve or deny the request. Implement:
   - navigation/deep-link from the notification to this approve-deny screen,
   - backend endpoints to approve or deny a join request and update challenge membership,
   - notify the requester of the outcome.

After the changes: flutter analyze clean, then build the latest APK and web (and deploy web).

4) INVITE -> OUT-OF-APP NOTIFICATION
   When a user is INVITED to a challenge, send an out-of-app (push) notification to the invited
   user: e.g. "<name> invited you to join the challenge <title>." Tapping it opens the challenge /
   invite so they can accept or decline. Use the existing push system (real OS delivery depends on
   FCM; in-app + logged push should work now).

5) PUBLIC SHAREABLE CHALLENGE INVITE LINK (no login required)
   - Let a challenge owner generate a PUBLIC invite link (shareable URL) for a challenge — both
     DURING challenge creation and AFTER, from the invite/challenge screen. Make it easy to copy/share.
   - Anyone with the link — even WITHOUT the app and WITHOUT an account — can open it on web and
     PARTICIPATE in the challenge WITHOUT being forced to log in or register. Do NOT gate joining
     behind auth. Use the existing guest-user model (users.is_guest / guest_created_at) so they can
     join and check in as a guest. Optionally offer (not force) creating a full account later to
     keep their progress.
   - Backend: a scoped public challenge-invite token + endpoints to join-as-guest and check in via
     that link. The token must ONLY allow joining/participating in that specific challenge — never
     broader account access.
   - Web: a public challenge landing page at the link showing the challenge details and a clear
     "Join / participate" action that works for guests (no auth wall).
